# Design

## Context

`app-foundation` 已建立 Flask app factory、教師 session、CSRF 驗證、SQLite 連線管理、統一 `AppError` 格式及 activities Blueprint 掛載點。notes 提供教師範圍清單查詢函式；目前活動模組仍為 placeholder。需求行為見 proposal.md 與 `specs/activities/spec.md`。

## Goals / Non-Goals

**Goals:**

- 以教師、課程、課堂、組別及活動的明確外鍵關係支援權限隔離與歷史保留。
- 讓活動狀態轉換、答案資格判定及答案寫入可在 SQLite 中序列化，供 quiz 共用同一交易。
- 讓學生加入證明獨立於組名，學生狀態回應依加入證明最小化資料。

**Non-Goals:**

- 不處理答案內容、重複提交政策、順位、結算、結果頁或回填／匯出；詳 proposal.md。
- 不修改 notes 的 `list_available_catalogs`、`get_catalog` 函式或資料表。

## Decisions

### 資料模型與清單版本

- 在共用資料庫新增 `courses`、課程清單關聯、`classrooms`、`teams`、學生加入證明及 `activities`、活動題目快照等資料。課程、課堂與活動均以不可變識別關聯至擁有教師；查詢子資源時也要沿關聯驗證所有權，不能只信任 URL 的 ID。
- 加入課程清單時先呼叫 `list_available_catalogs(teacher_id)` 驗證清單，再於建立活動時呼叫 `get_catalog(teacher_id, import_id, import_version)`，將清單識別、版本、題目識別、顯示題號及順序保存為活動快照。活動題目快照不存題目敘述；活動顯示仍只需題號。不得直接讀 notes 表。
- 以固定長度的 6 碼字元集（大寫字母與數字，排除 `0/O/1/I`）產生加入碼；遇到進行中課堂衝突時重新產生，資料庫以唯一性約束作最後防線。不同課堂同名 team 以 `classroom_id` 範圍隔離。
- 組名正規化先 trim 並把連續空白折為單一空白，長度 1–20；查找時用 Unicode casefold 後的正規化鍵，保留原始顯示名稱。此規則是本組自行決定的預設。

### 加入證明與學生資料界線

- 每次成功加入產生獨立隨機 token，透過 `HttpOnly` cookie 傳遞；cookie 設 `SameSite=Lax`，本機 HTTP 開發環境不強制 Secure，正式 HTTPS 部署再啟用 Secure。資料庫只保存 token 的密碼學雜湊及其 team/classroom 關聯。重新整理由 cookie 對應回原授權；同組另一瀏覽器仍須另行加入並取得另一 token。
- 加入證明驗證失敗、已撤銷或不符課堂時回一般拒絕，不提供組別存在性或資料。對學生狀態 API 只序列化課堂名稱、該瀏覽器所屬組名、目前活動名稱／階段／題號及狀態版本；不可把其他 team、答案或題目敘述載入該回應 DTO。

### 活動狀態與交易邊界（quiz 介面）

- 狀態限制為 `preparing`、`active`、`ended`。開始及結束均以單堂活動集合的資料庫約束／交易檢查維持唯一 active 活動；結束後不允許轉回其他階段。關課與結束活動更新課堂、活動及狀態版本必須使用相同寫入交易邊界。
- quiz 的介面提供兩層職責：外層由 quiz 擁有答案寫入交易並先執行 `BEGIN IMMEDIATE`；在該連線／交易內呼叫 activities 的資格檢查（輸入 classroom、activity、team、question 識別，輸出允許或穩定錯誤代碼），接著 quiz 寫入答案並提交同一交易。資格檢查不得自行提交、開新連線或在返回後釋放交易鎖。它檢查課堂仍進行中、活動仍 active、活動屬於該課堂、team 屬於該課堂及 question 在活動快照中。
- activities 的開始、結束、關課命令也使用 `BEGIN IMMEDIATE`，在取得寫入鎖後重新讀取權威狀態再驗證轉換並提交。若答案交易先取得鎖且資格有效，答案可先受理再由結束交易完成；若結束／關課交易先提交，之後資格檢查必定拒絕。以資料庫交易提交作為「確認受理／確認結束」的線性化點，符合 D02 截止一致性。
- 建議資格介面錯誤代碼：`ACTIVITY_NOT_ACTIVE`、`CLASSROOM_CLOSED`、`ACTIVITY_CLASSROOM_MISMATCH`、`TEAM_CLASSROOM_MISMATCH`、`QUESTION_NOT_IN_ACTIVITY`。對外 HTTP 層轉成共用錯誤格式；quiz 內部可直接依代碼分支。

### 狀態同步與頁面

- 學生與教師頁面每約 1 秒輪詢權威狀態 API。每堂保存遞增整數 `state_version`，任何影響呈現的加入、活動轉換或關課狀態變更時遞增；API 將版本與快照一併回傳。前端僅套用大於已套用版本的快照，避免網路延遲造成倒退。（R08）
- 目前活動依序選取：搶答中活動；否則最新建立的準備中活動；否則最近結束的活動；皆無才回傳等候狀態。結束活動後，下一活動開始前學生仍看到最近結束活動的「已結束」階段及題號。若課堂已關閉，學生狀態額外標示「課堂已結束」，並依同一選取順序顯示最近可顯示活動的階段與題號；沒有活動時只顯示課堂已結束及等候／無活動狀態。已加入學生仍以有效加入證明查詢此狀態，結果查看（D16）由 quiz change 提供。教師開始活動後的下一次輪詢即更新，目標 2 秒內反映。前端不以客戶端狀態決定授權或轉換。
- 教師端以既有登入 `teacher_id` 做所有讀寫授權，教師頁提供課程列表、課程清單／課堂管理與課堂控制；狀態變更沿用既有 CSRF 機制。學生頁只使用加入證明，不建立學生帳號。

### 錯誤、初始化及敏感設定

- 可預期拒絕沿用 `AppError` 的 `{error:{code,message}}` 格式。未知或無權資源採不洩漏存在性的通用訊息。初始化命令須建立新 schema；使用者資料只存加入 token 雜湊。教師密碼雜湊、secret key 與 OAuth 路徑仍遵守 app-foundation；本 change 不加入任何真實憑證或機敏值。
- schema 以 `CREATE TABLE IF NOT EXISTS`／明確版本升級策略維護；此 change 的本機驗收使用新空白資料庫及示範目錄，避免破壞既有 foundation 帳號資料。

### 考慮過的替代方案

- 將加入證明直接當組別 token：不採用，因為會讓同組不同瀏覽器不能各自授權，也會把可猜的組名誤當秘密。
- 只在 Flask route 檢查答案資格，再讓 quiz 另開交易：不採用，因為檢查與寫入間可插入結束活動，破壞 D02 截止一致性。
- 以輪詢時間戳排序狀態：不採用，使用單堂遞增版本能直接拒絕舊快照且不依賴客戶端時鐘。

## Risks / Trade-offs

- **SQLite 寫入交易會序列化相同資料庫的狀態變更與答案寫入** → 交易內只做必要查詢與寫入，不執行 notes 外部操作或長時間工作；若未來併發需求超出本機課堂規模，再評估其他資料庫。
- **加入碼隨機碰撞可能使建立課堂重試** → 使用資料庫唯一約束並有限次重產，耗盡時回傳可辨識的暫時錯誤，不建立無碼課堂。
- **同組可在不同瀏覽器加入是產品規則，無法證明操作者身分** → 各瀏覽器以自己的隨機加入證明授權，組名只決定分組，不作為身份驗證。
- **輪詢有固定請求成本且網路可能延遲** → 約 1 秒輪詢並用狀態版本丟棄舊回應；驗收以實際操作量測 2 秒目標。

## Migration Plan

以新的 schema 初始化或升級本機 SQLite，保留既有教師資料；新資料表與教師頁面同版部署。回退時停用 activities Blueprint 路由並保留新增資料表，避免刪除已建立的課堂與歷史資料。資料庫備份後可再移除功能，但不在本 change 提供破壞性清除遷移。

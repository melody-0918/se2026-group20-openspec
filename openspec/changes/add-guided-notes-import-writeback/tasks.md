# Tasks

## 1. A／B 介面與整合準備

- [ ] 1.1 與 B 核對課程授權、歷史活動回填入口、Blueprint 及資料庫接點，以及清單與結算快照欄位。驗證方式為雙方用同一組單題、兩格題組、無勝組、已結束未結算的樣本核對輸入、輸出，並記錄 `RESULT_NOT_READY` 和其他已同意的錯誤回應。
- [ ] 1.2 建立 Notes Blueprint 與 Notes 儲存介面，接到 B 的 app factory、資料初始化與教師授權；將業務邏輯保留在可獨立測試的模組。驗證方式為使用測試 app 檢查路由可註冊，且資料初始化與權限檢查沿用 B 的共用入口。

## 2. Desktop OAuth 與 Sheets 存取

- [ ] 2.1 建立本機授權指令，從 `NOTES_GOOGLE_CLIENT_SECRETS`、`NOTES_GOOGLE_TOKEN` 取得 repo 外檔案路徑，並在 README 補上占位範例、授權及重新授權步驟。驗證方式為以隔離檔案路徑測試設定及命令，檢查 diff、回應及日誌未帶入機敏值。
- [ ] 2.2 接入 Sheets 分頁資料、合併範圍讀取、答案格寫入與回讀；區分授權失效、來源無權限及外部讀寫失敗。驗證方式為以測試替身模擬過期 token、權限拒絕及網路錯誤，核對教師提示且一般 HTTP 請求不啟動 Google 登入。

## 3. 匯入、解析、預覽與版本

- [ ] 3.1 實作動態表頭、正整數主題號和單題答案格辨識。驗證方式為使用欄列位置不同、表頭前後帶空白或合併的測試資料，核對題數、題號、順序及格位，並確認缺少或重複表頭及歧義能被拒絕。
- [ ] 3.2 依主題號合併範圍辨識題組，區分半形與全形括號的小題標號、答案格及其合併格左上角，並擷取題目與小題文字。驗證方式為測試混合版面的三種計數、題組以外的空白題號列，以及文字輸出不含作答格內容。
- [ ] 3.3 建立課程內預覽、確認保存與版本清單。D17 的命名、來源資訊與逐分頁預設依兩組確認狀態標示。驗證方式為測試合法課程可保存確認的預覽、未授權課程無法查詢或保存，且新版本不覆寫舊版本；如採 D17，另核對所選分頁的預覽、名稱與保存範圍。
- [ ] 3.4 提供 `CatalogDTO` 介面，將固定的題目、填空識別及順序交給 B，供建立活動時選用版本。驗證方式為以契約測試比較匯入前後的資料，確認 B 仍可取得既有活動原版本及題目文字，且不取得格位或憑證。

## 4. 結算後回填、重檢與恢復

- [ ] 4.1 接入 `get_ended_snapshot()` 並驗證活動、清單版本、題目、填空與教師權限。驗證方式為以契約測試覆蓋未結算、版本或識別錯誤、狀態不符、未獲授權、無勝組及題組同一勝組的完整答案，並檢查拒絕情境未呼叫 Sheets 寫入。
- [ ] 4.2 產生回填預覽，確認前重查來源位置、題目和原值，處理預覽失效及須重新匯入。驗證方式為在測試替身移動欄列、編輯目標原值、移除一題，確認前兩種需重新確認，最後一種不寫入也不改綁既有活動。
- [ ] 4.3 僅寫目標答案格，加入逐格回讀及續填，保留小題標號、合併格式及原勝組。驗證方式為模擬寫入成功但回讀不符、回應中斷、部分完成和他人改值，檢查已完成格未重寫、未驗證與衝突狀態正確，且只有安全的未完成格可續寫。

## 5. 跨模組人工驗收

- [ ] 5.1 人工執行 A01、A02。用單題範本副本和**另一份題數不同、表頭與作答欄已移動的 Guided Notes** 實際匯入、預覽、保存並回填；第二份須含跨列題組及合併答案格。驗證方式為逐題對照兩份來源的題號、三種計數、答案格、標號與格式，並確認未指定的格位保持原值。
- [ ] 5.2 人工驗證 A 的 A07、A08。保留一題無勝組，並分別在預覽後移動來源、改變題目集合，以及模擬回填中斷後重試。驗證方式為在原表核對無勝組略過、來源異動須重新確認或匯入、已回填格由回讀識別，以及外部改值時有衝突提示。
- [ ] 5.3 與 B 在本機用一位教師及至少兩個學生組別走完活動。驗證方式為讓兩組提交同一題組，教師在結算後回填，再對照 B 的勝組及原表中所有小題答案。記錄人工驗收的執行者、日期、版本、輸入、預期與實際結果，並附去除機敏資料的畫面或日誌。

# Tasks

正式講義的自動測試與人工驗收均使用 `GUIDED_NOTES_DEMO_CATALOG=0` 或未設定的環境；另以啟用旗標的 Foundation 測試保留示範清單相容性。

## 1. A／B 介面與整合準備

- [ ] 1.1 與 B 核對 D15 課程歸屬與篩選責任、D19 題目文字交付方式、歷史活動權限、`get_ended_snapshot()` 的接點、欄位及錯誤回應。驗證方式為以單題、兩格題組、無勝組和已結束未結算的樣本核對輸入、輸出，記錄待確認事項的結論及仍未定案的部分。
- [ ] 1.2 擴充現有 `notes.bp` 的教師路由，沿用 `/notes` 掛載、Flask session 與全域 CSRF，並透過共用 `get_db()` 和 `init-db` 建立 Notes 資料表。驗證方式為在測試 app 檢查既有占位頁、未登入或失效教師拒絕、缺少 CSRF 時不寫入，以及初始化空白和已有教師資料的 SQLite，確認重跑仍保留資料。

## 2. Desktop OAuth 與 Sheets 存取

- [ ] 2.1 建立本機授權指令，從 `NOTES_GOOGLE_CLIENT_SECRETS`、`NOTES_GOOGLE_TOKEN` 取得 repo 外檔案路徑，並在 README 補上占位範例、授權及重新授權步驟。驗證方式為以隔離檔案路徑測試設定及命令，檢查 diff、回應及日誌未帶入機敏值。
- [ ] 2.2 沿用 `google_credentials_paths()` 的延遲檢查，接入 Sheets 分頁資料、合併範圍讀取、答案格寫入與回讀。驗證方式為模擬缺少設定、過期 token、來源權限拒絕及網路錯誤，核對 `GOOGLE_CREDENTIALS_REQUIRED` 和相應教師提示，確認啟動和 SQLite 清單查詢無須 Google 憑證、一般 HTTP 請求不啟動 Google 登入。

## 3. 匯入、解析、預覽與版本

- [ ] 3.1 實作動態表頭、正整數主題號和單題答案格辨識。驗證方式為使用欄列位置不同、表頭前後帶空白或合併的測試資料，核對題數、題號、順序及格位，並確認缺少或重複表頭及歧義能被拒絕。
- [ ] 3.2 依主題號合併範圍辨識題組，區分半形與全形括號的小題標號、答案格及其合併格左上角。驗證方式為測試混合版面的三種計數、題組以外的空白題號列和作答格定位；D19 文字串接確認後，另驗證文字來源不含作答格內容。
- [ ] 3.3 建立匯入預覽、確認保存及正式講義版本持久化，透過 `_catalogs_for_teacher()` 提供可讀清單。課程內選用依 D15 確認的授權接點整合，D17 維持待確認的預設。驗證方式為確認未保存預覽不列入、保存失敗不留部分資料、成功保存後可重讀，且新版本保留舊版；D15 接通時核對未授權課程無法查詢或保存。
- [ ] 3.4 以正式 SQLite 資料驗證 `list_available_catalogs(teacher_id)` 和 `get_catalog(teacher_id, import_id, import_version)`。驗證方式為比較摘要、明細與 Foundation 既有欄位，核對單題恰有一個 item、題組的 `label`／`order` 與來源一致，以及保存新版並重新載入後舊版的 `question_id`、`item_id`、`display_number` 和順序不變。確認未回傳作答格內容、格位或憑證。
- [ ] 3.5 驗證兩個查詢的教師隔離、精確版本與示範相容性。驗證方式為以兩位教師及不同版本核對清單可見範圍，斷言其他教師的清單、未知講義或未知版本均回相同 `CATALOG_NOT_FOUND`（404），且不回傳其他版本；無效教師查詢皆回 `TEACHER_REQUIRED`（401）。另在隔離測試中啟用示範旗標，確認既有示範資料仍可讀。

## 4. 結算後回填、重檢與恢復

- [ ] 4.1 驗證活動、固定清單版本、題目、填空及教師權限，待 B 確認後接入 `get_ended_snapshot()`。驗證方式為先以結算測試替身覆蓋未結算、版本不符、未知或重複 `question_id`、缺少、重複或未知 `item_id`、未獲授權、無勝組及同一勝組的完整題組答案。確認拒絕情境未呼叫 Sheets 寫入，串接後依雙方確認的錯誤回應重驗。
- [ ] 4.2 產生回填預覽，確認前重查來源位置、題目和原值，處理預覽失效及須重新匯入。驗證方式為在測試替身移動欄列、編輯目標原值、移除一題，確認前兩種需重新確認，最後一種不寫入也不改綁既有活動。
- [ ] 4.3 僅寫目標答案格，加入逐格回讀及續填，保留小題標號、合併格式及原勝組。驗證方式為模擬寫入成功但回讀不符、回應中斷、部分完成和他人改值，檢查已完成格未重寫、未驗證與衝突狀態正確，且只有安全的未完成格可續寫。

## 5. 跨模組人工驗收

- [ ] 5.1 人工執行 A01、A02。用單題範本副本和**另一份題數不同、表頭與作答欄已移動的 Guided Notes** 實際匯入、預覽、保存並回填；第二份須含跨列題組及合併答案格。驗證方式為逐題對照兩份來源的題號、三種計數、答案格、標號與格式，並確認未指定的格位保持原值。
- [ ] 5.2 人工驗證 A 的 A07、A08。保留一題無勝組，並分別在預覽後移動來源、改變題目集合，以及模擬回填中斷後重試。驗證方式為在原表核對無勝組略過、來源異動須重新確認或匯入、已回填格由回讀識別，以及外部改值時有衝突提示。
- [ ] 5.3 與 B 在本機用一位教師及至少兩個學生組別走完活動。驗證方式為讓兩組提交同一題組，教師在結算後回填，再對照 B 的勝組及原表中所有小題答案。記錄人工驗收的執行者、日期、版本、輸入、預期與實際結果，並附去除機敏資料的畫面或日誌。

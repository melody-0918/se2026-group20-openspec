# Design

## Context

目前使用 Flask/Jinja 的 10 個獨立 HTML 模板，沒有共用 CSS；`guided_notes/static/` 尚不存在。模板包含教師、學生、notes 與錯誤頁，其中學生頁內容由既有 JavaScript 動態產生，教師課堂頁的題目結果也由輪詢程式動態更新。詳見 proposal.md 的動機與 capability 規範。

## Goals / Non-Goals

**Goals:**

- 以一致字體、寬度、間距和元件樣式提高可讀性，適合投影及錄影。
- 讓學生題目、各活動階段及教師題目作答狀況具有清楚的視覺層級。
- 保留現有介面與行為，使樣式變更可透過模板呈現層完成。

**Non-Goals:**

- 不改任何頁面文字、元素 `id`、表單欄位 `name` 或連結網址。
- 不改 JavaScript 邏輯、後端程式、API、資料結構或功能流程。
- 不新增外部框架、CDN、網路字體或執行期網路依賴。

## Decisions

### 共用樣式檔與引用方式

- 新增 `guided_notes/static/app.css`，使用 Flask 應用程式既有的靜態檔提供方式；各模板在 `<head>` 以 `url_for('static', filename='app.css')` 引用，並可加入 viewport meta。
- 每一頁直接引用同一份檔案，避免新增模板繼承架構或建立多份樣式入口。替代方案是每頁內嵌 CSS，會造成規則重複且難以一致維護。
- `notes.html` 可補上標準 `<head>` 結構以容納 meta 與樣式連結；需告知組員 A，模板文字、欄位、網址與功能維持不變。

### 視覺基礎

- 採用本機系統字體堆疊與繁體中文常見 fallback（例如 `system-ui`、`"Microsoft JhengHei"`、`sans-serif`），不載入網路字體。正文基準字級約 18px，標題層級清楚，行高約 1.6。
- 主內容使用置中容器，最大寬度約 1120px，窄螢幕留有側邊距；以一致的區塊間距、表單欄位間距和標題間距建立節奏。
- 連結與按鈕採明確對比、可辨識的互動狀態與足夠點擊範圍；輸入框、選單、焦點與停用狀態需清楚可見。表單標籤和欄位保持整齊排列，窄畫面可自然換行。
- 清單以一致的區塊間距、邊框或背景區分項目。學生頁各題呈現為卡片，題目文字、作答欄、提交提示及回覆狀態各有層級。
- 學生活動階段以醒目的文字標籤呈現「準備中／搶答中／已結束」；等候狀態與課堂已結束也維持清楚的文字層級。顏色、邊框或圖示只能輔助辨識。
- 教師課堂頁每題作答狀況以分題區塊或卡片呈現，組別、順位與答案易於掃視；勝組同時使用清楚的「勝組」文字標籤及輔助視覺強調。
- notes 頁表格提供清楚的表頭、列間距、邊框和可閱讀的儲存格留白；窄螢幕容許表格水平捲動，不改表格內容。
- 錯誤頁以清楚的標題、警示訊息、錯誤代碼和返回連結形成明確層級；保留文字訊息本身，不以顏色單獨表示錯誤。
- 色彩選擇需維持足夠文字與背景對比，並顧及停用、焦點及錯誤狀態。色彩不承擔唯一語意。

### 模板改動邊界

- 只在既有元素新增 class、加入純版面容器，以及在 head 引用共用 CSS／加入 viewport meta；`notes.html` 另允許補上正確的 `<head>` 結構。
- 不改任何顯示文字、元素 `id`、表單欄位 `name`、連結網址、JavaScript 邏輯或後端程式。現有內嵌 JavaScript 與表單行為保持原樣。
- 動態建立的學生題目與教師作答狀況，透過既有結構或其父層選擇器套用樣式；若要增加 class，只能調整既有呈現節點的 class，不改資料、事件或流程邏輯。

### 測試與驗收

- 新增自動測試遍歷所有使用者 HTML 頁面，確認引用同一共用樣式 URL，並確認靜態資源回應成功。既有測試不修改；完整套件需維持 91 passed。
- 人工示範驗收逐頁檢查登入、首頁、課程列表、課程頁、課堂頁、加入頁、學生頁各階段、notes 頁及錯誤頁；確認原功能流程正常，並截圖教師課堂頁與學生頁供確認。

### 模組介面與機敏資料

- 本 change 不改 Blueprint、路由、API、錯誤代碼或模組間資料介面。模板只引用 Flask 提供的共用靜態資源；notes 頁只新增呈現樣式引用與必要結構。
- 不新增或改動機敏設定；教師密碼、secret key 與 Google OAuth 檔案／token 的既有 repo 外存放方式維持原樣。

## Risks / Trade-offs

- [學生與教師內容由 JavaScript 動態產生，單靠初始模板樣式可能無法涵蓋] → 以既有 DOM 結構與穩定 class／父層選擇器設計 CSS，並將準備中、搶答中、已結束和勝組畫面納入人工檢查。
- [全域元素選擇器可能影響不同模組的特殊版面] → 以共用基礎規則搭配少量頁面／區塊 class，避免過度寬泛的版面選擇器。
- [增加字級與間距可能使內容高度增加] → 以投影可讀性為優先，同時檢查長清單、表格及窄視窗的捲動與換行。

## Migration Plan

1. 新增共用 CSS 與頁面引用，對既有元素補上樣式所需的 class 或純版面容器。
2. 執行新增靜態樣式測試及既有 `python -m pytest`；確認 91 passed。
3. 依 tasks.md 的示範模式逐頁驗收並保存教師課堂頁與學生頁截圖。
4. 若呈現有問題，回復共用 CSS 或模板新增的 class／容器／head 引用即可；不涉及資料遷移。

## Open Questions

無。字級、容器寬度及色彩細節可在實作與示範檢視時微調，不改變本 change 的需求或架構。

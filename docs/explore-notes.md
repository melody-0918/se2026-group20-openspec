# A 模組（notes）OpenSpec Explore 紀錄

這份紀錄整理兩輪 Explore。第一輪依當時確認的分工，釐清 A 的工作、可獨立開發的部分，以及與 B 的交接。第二輪核對合併後的 `main`（`b09520f`），以新版 `config.yaml`、`README.md` 和兩組共同需求文件更新結論。 [專案設定](../openspec/config.yaml)、[README](../README.md)、[共同需求文件](https://github.com/Afra0704/se2026-group20-speckit/blob/master/docs/shared-requirements.md)

## 探索目標與討論範圍

釐清教師如何在課程內匯入、預覽及選用 Guided Notes，系統如何從不同版面的 Google Sheets 辨識單題與題組，以及活動結算後如何把勝組答案填回原表。我們也討論了 Google 授權、CSV 匯出、講義版本與活動的關聯，以及 A、B 各自能先開發哪些部分。

## 已確認決策與理由

| 已確認決策 | 理由或影響 |
| --- | --- |
| **A 負責 `notes` 與 CSV 的分工，B 負責 `activities`、`quiz` 與共用骨架。** A 維護匯入、辨識、版本與回填，以 Blueprint 接入 B 建立的 Flask app、教師登入和資料庫。 | A 管理講義及原表格位，B 管理活動、提交與結算。CSV 有主責人，交付範圍仍待兩組確認。 |
| **題組已納入本次實作（D05、D10）。** 每個主題號是一題及一個提交單位，所有小題一起送出，整題只有一個順位和一個勝組。題數、提交單位數及作答格數分開計算。 | 題組的全部答案都來自同一勝組。A、B 必須沿用同一組填空識別碼，才能逐格回填。 |
| **依版面動態辨識（R02、R10、R11、D05）。** 根據同列表頭、正整數題號與合併範圍定位。空白題號列不能自動歸到上一題。答案寫入標號右側的答案區，合併答案格寫左上角，保留標號與格式。 | 欄列移動後仍可辨識同一題與小題，避免把答案寫到標號或其他題目的格位。 |
| **採 Desktop OAuth 存取 Sheets。** 使用 `google-api-python-client` 與 `spreadsheets` 讀寫 scope。OAuth client 檔及 token 由環境變數指定 repo 外路徑。一般 HTTP 請求不觸發 Google 登入，token 失效時提示重新授權。 | 教師的系統登入由 B 管理，Sheets 讀寫授權由 A 處理。前一輪討論的網頁 OAuth 與 Picker 屬於當時評估過的方案。 |
| **建立活動時固定講義版本（D11、D12–D16）。** 教師先選課程，再匯入或選擇該課程的講義版本。改用新版本須建立新活動。 | 既有活動的作答、結算與回填可持續對應原始題目和填空。 |
| **以已結算結果回填，並回讀確認（D07、D09）。** 略過無勝組題目。來源變動時重建預覽並再次確認，題目集合改變時須重新匯入。回讀相同才算完成，內容不符時提示衝突。 | 避免來源變動造成錯位，也讓重試時能辨認已完成的格位。 |

## A／B 模組介面

| 方向 | 已有共識 | 還要確認 |
| --- | --- | --- |
| **A → B：講義清單** | 共同設計已記錄 `CatalogDTO`、`import_id`、`import_version`、`question_id` 與有序的 `items`。B 建立活動時固定清單，A 管理實際 Sheets 格位。 | 填空識別碼如何從清單沿用到提交、結算及回填，以及 D19 的題目與小題文字如何傳給 B。 |
| **B → A：身分、課程與活動** | B 提供教師身分、課程、課堂及活動。A 提供教師可存取的課程講義和版本。 | 共用識別碼、權限檢查入口，以及關課後如何授權存取歷史活動進行回填。 |
| **B → A：結算快照** | 共同設計已記錄 `get_ended_snapshot()`。活動已結束且結算完成才提供不可變結果，未就緒回 `RESULT_NOT_READY`。 | 快照的完整欄位、無勝組的表示、勝組答案與填空 ID 的對應。若納入 CSV，再確認各組答案、順位及勝組欄位。 |
| **共用 Flask／SQLite** | B 先建立共用骨架，A 註冊 `notes` Blueprint。 | Blueprint 掛載、設定、登入與資料庫的接入方式，以及函式輸入、輸出和錯誤碼。 |

**討論中的實作建議**是先用測試資料驗證解析、重新定位與回填計畫，以模擬快照核對資料交接。OAuth 與 Sheets 讀寫可用測試表獨立驗證。正式的權限檢查、活動版本綁定和結算後回填，則依賴 B 的共用骨架與結果介面。

## 未決問題

- **提交與順位。** D01 的有效提交、空白與重送處理，D02 的伺服器受理序號排序，以及 D08 是否只依順位決定勝組，仍是待確認的預設。D02 的截止原則已確認，只有系統確認結束前成功受理的答案才計入。
- **講義與 CSV。** D17 的分頁命名、逐頁選擇與保存仍待兩組確認。CSV 是否交付也未定案，列的粒度、題組呈現、未作答組別及排序都曾討論，尚未選定。
- **共同文件與本地摘要的差異。** D13 在共同文件中限制同堂最多一個未結束活動，包含準備中，本地摘要只寫搶答中。D19 記錄了完整題目與小題文字，需與 B 對齊清單欄位。D20 教師 Google 登入與 D21 Drive 選檔、講義移除仍缺 OpenSpec 同步確認。 [共同需求文件](https://github.com/Afra0704/se2026-group20-speckit/blob/master/docs/shared-requirements.md)

## 如何銜接 Propose

**建議 change 名稱為 `add-guided-notes-import-writeback`。** 提案前先和 B 用單題、兩格題組、無勝組、已結束但未結算四種樣本對齊講義清單和結算快照，再確認教師權限與歷史活動的回填入口。

核心 change 建議涵蓋課程內匯入、預覽與版本清單、單題及題組辨識、Desktop OAuth、清單介面，以及依結算快照回填、重建預覽、回讀和重試。共用骨架、教師登入、課堂管理、輪詢、作答受理、順位與結算由 B 的 change 處理。CSV 建議待兩組確認交付後另立 change。

進入 Propose 時，將範圍與待確認項寫入 `proposal.md`，以 R02、R10、R11 及相關 D 編號撰寫差異規格，在 `design.md` 定義模組介面與錯誤回應，並在 `tasks.md` 保留 A01、A02、A07、A08 的驗收。共同驗收要用不同版面的講義實際匯入與回填，並讓兩組學生提交題組，確認原表收到同一勝組的全部小題答案。
